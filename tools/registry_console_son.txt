# Les SIX clefs que Game.exe 1.14d lit VRAIMENT sous
# HKCU\Software\Blizzard Entertainment\Diablo II (fonction 0x514b60, chaines
# 0x6dea7c..0x6deac8, verifiees au desassemblage ET par grep dans Game.exe) :
#
#   Sound Mixer      -> 0x8817ac  defaut 0    REJETE si >= 3
#   Master Volume    -> 0x8817b0  defaut 100  REJETE si > 100
#   Music Volume     -> 0x8817b4  defaut 50   REJETE si > 100
#   Positional Bias  -> 0x8817b8  defaut 50   REJETE si > 100
#   NPC Speech       -> 0x8817bc  defaut 2    REJETE si >= 3
#   Options Music    -> 0x8817c0  defaut 1    REJETE si > 1
#
# Le volume applique a une voix vaut vol * MusicVolume/100 * MasterVolume/100
# (0x4dfc84 puis 0x4dfca1) : ces deux clefs sont le SEUL chemin registre -> son.
#
# CE QUI A ETE CORRIGE LE 06/09. La version precedente de ce fichier posait
# « Sound Volume », « 3D Sound », « Environmental Sound » et « 3D Bias » : ces
# QUATRE noms n'existent PAS dans Game.exe 1.14d (grep -aiob : aucune
# occurrence), ce sont des noms de l'ere 1.09. Elles etaient donc INERTES, et
# « Music Volume = 0x80 » (128) etait REJETE par le test > 100 de 0x514bfc : la
# musique restait au defaut 50. C'est pour cela que §11.4 avait mesure « le
# registre ne change rien » — le registre ne changeait rien PARCE QUE les clefs
# etaient fausses. Ne jamais reintroduire ces quatre noms.
#
# Sound Mixer reste a 0 (2D stereo) : c'est le seul mode que le melangeur
# implemente, et le jeu le forcerait a 0 de toute facon (0x4e0050) puisque
# GetCaps rend dwMaxHw3DAllBuffers = 0.
